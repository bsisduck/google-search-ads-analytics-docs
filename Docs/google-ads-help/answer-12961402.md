The integration with a third-party App Attribution Partner (AAP) can offer seamless conversion tracking by allowing you a trusted way to [link a provider](https://support.google.com/google-ads/answer/7365001) and [import conversions](https://support.google.com/google-ads/answer/7382633) to Google Ads.

* [How a third-party AAP integration works](#how_3P_AAP_works)
* [Reduce third-party AAP reporting discrepancies](#reduce_3P_AAP_discrepancies)

---

Benefits
--------

* Streamlined integration
* Early access to new measurement features compared to other third-party app analytics providers
* Reduced reporting discrepancies between Google Ads and your app analytics
* Easier import of the data you want into Google Ads

How a third-party AAP integration works
---------------------------------------

Google Ads partners with several third-party app analytics providers to track app conversion analytics. You can learn more about how this integration works below:

### Enable Google Ads app conversion tracking using a third-party AAP

Google’s App Attribution Partner (AAP) program provides third-party app analytics certification for the following select mobile measurement partners. This collaboration ensures access to best-in-class analytics for your Google Ads campaigns. Click your chosen third-party provider below to get started:

|  |  |
| --- | --- |
|  | [Adjust Integration](https://help.adjust.com/en/article/google-ads) |
|  | [Airbridge Integration](https://help.airbridge.io/en/guides/google-ads-channel-integration) |
|  | [AppsFlyer Integration](https://support.appsflyer.com/hc/en-us/articles/115002504686-Google-Ads-AdWords-integration-setup) |
|  | [Branch Integration](https://help.branch.io/using-branch/docs/google-ads) |
|  | [Kochava Integration](https://support.kochava.com/campaign-management/google-ads/) |
|  | [Singular Integration](https://support.singular.net/hc/en-us/articles/115003252786-Google-Ads-AdWords-Mobile-Attribution-Integration) |
|  | [Tenjin Integration](https://docs.tenjin.com/docs/google-ads?highlight=Google%20Ads) |

The methods through which you can pass app conversions and user consent to analytics providers are detailed below.

**Important**: Please ensure that consent status for EEA users is captured before sending app conversions to your third-party AAP. In the scenario a conversion is passed and user-level consent has not been granted, Google Ads may use the gbraid for non-user level app conversion measurement.

Collect app conversion events and user consent through a third-party AAP SDK integration
----------------------------------------------------------------------------------------

Leverage third-party AAP SDK integration to collect and pass app conversion events, referrer, and consent status to Google Ads for campaign attribution and optimization. Click on your chosen provider below to configure a third-party SDK:

#### Adjust:

1. Integrate the [Adjust SDK](https://help.adjust.com/en/article/getting-started-with-adjust#integrate-the-sdk).
2. Follow these [Android](https://help.adjust.com/en/article/deep-linking-android-sdk#reattribution-deep-links) and [iOS](https://help.adjust.com/en/article/deep-linking-ios-sdk?src=search#reattribution-deep-links) deeplink guides to ensure that Google can receive referring URL click identifiers from Adjust for attribution.
   * **Note**: The Adjust Android SDK v4.12+ is required for compatibility, however all Adjust iOS SDK versions are compatible.
3. Activate Integrated Conversion Measurement in the Adjust user interfaceI by ensuring that “[Probabilistic Modeling”](https://help.adjust.com/en/article/attribution-methods#probabilistic-modeling) (disabled by default), and the [Attribution Window for Probabilistic Modeling](https://help.adjust.com/en/article/attribution-windows#attribution-1) is set to 24 hours (6 hours by default).
   * **Note**: The Adjust [iOS SDK v5.4.1+](https://github.com/adjust/ios_sdk/releases) and [Adjust ODM plugin](https://dev.adjust.com/en/sdk/ios/plugins/google-odm) are required for compatibility. However, all Adjust Android SDK versions are compatible. Additionally for iOS, either the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required.
4. Provide [consent status](https://help.adjust.com/en/article/privacy-features-android-sdk#provide-consent-data-to-google-digital-markets-act-compliance) for EEA users by following these [Android](https://help.adjust.com/en/article/android-sdk-adjust-class#change-third-party-sharing) and [iOS](https://help.adjust.com/en/article/ios-sdk-adjust-class#third-party-sharing) compliance guides and ensure "addGranularOption" for [third-party sharing](https://help.adjust.com/en/article/block-third-party-data) is enabled. For optimal performance, delay SDK data transmission until consent status is captured. For Android, implement the `Adjust.setOfflineMode` method. For iOS, implement either the `setOfflineMode` method, `requestTrackingAuthorizationWithCompletionHandler` method, or `requestTrackingAuthorization` method.
   * **Note**: The Adjust [Android SDK v4.26.0+](https://github.com/adjust/android_sdk/releases) and [iOS SDK 4.25.0+](https://github.com/adjust/ios_sdk/releases) are required for compliance.

#### Airbridge:

1. Integrate the [Airbridge SDK](https://help.airbridge.io/en/developers/airbridge-sdk-overview).
2. Follow these [Android](https://help.airbridge.io/en/developers/android-sdk#deep-link-setup) and [iOS](https://help.airbridge.io/en/developers/ios-sdk#deep-link-setup) deeplink guides to ensure that Google can receive referring URL click identifiers from Airbridge for attribution.
   * **Note**: All Airbridge SDK versions are compatible.
3. Activate Integrated Conversion Measurement in the Airbridge user interface by ensuring the [Lookback Window](https://help.airbridge.io/en/guides/setting-attribution-window) for [Probabilistic Modeling Matching](https://help.airbridge.io/en/guides/setting-attribution-window#how-to-view-the-settings) is set to 24 hours or longer (24 hours by default) for Google Ads.
   * **Note**: The Airbridge [iOS SDK v4.4.1+](https://help.airbridge.io/en/developers/release-note-ios-sdk) is required for compatibility. However, all Airbridge Android SDK versions are compatible. Additionally for iOS, either the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required.
4. Provide [consent status](https://help.airbridge.io/en/guides/supporting-the-updated-google-eu-user-consent-policy#option-1-sharing-consent-values-using-the-airbridge-sdk) for EEA users by following these [Android](https://help.airbridge.io/en/developers/android-sdk#dma-compliance-setup) and [iOS](https://help.airbridge.io/en/developers/ios-sdk#dma-compliance-setup) compliance guides. For optimal performance, delay SDK initialization or data transmission until consent status is captured. For Android, implement the `autoStartTrackingEnabled` method. For iOS, implement the `autoStartTrackingEnabled` method.
   * **Note**: All Airbridge SDK versions are compliant.

#### AppsFlyer:

1. Integrate the [AppsFlyer SDK](https://support.appsflyer.com/hc/articles/207032126-SDK-integration-overview).
2. Follow this [deeplink guide](https://www.appsflyer.com/resources/guides/deep-linking-for-developers/) to ensure that Google can receive referring URL click identifiers from AppsFlyer for attribution.
   * **Note**: The AppsFlyer [Android SDK v4.8.5+](https://dev.appsflyer.com/hc/docs/android-release-notes) is required for compatibility. However, all AppsFlyer iOS SDK versions are compatible.
3. Activate Integrated Conversion Measurement in the AppsFlyer user interface by ensuring that “Advanced Data Sharing” is enabled (disabled by default) for Google Ads.
   * **Note**: The AppsFlyer [iOS SDK v6.17.1+](https://dev.appsflyer.com/hc/docs/ios-release-notes) is required for compatibility. However, all AppsFlyer Android SDK versions are compatible. Additionally for iOS, either the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required.
4. Provide [consent status](https://support.appsflyer.com/hc/en-us/articles/22310731147153-Supporting-the-Google-EU-consent-policy) for EEA users by following these [Android](https://dev.appsflyer.com/hc/docs/android-send-consent-for-dma-compliance) and [iOS](https://dev.appsflyer.com/hc/docs/ios-send-consent-for-dma-compliance) compliance guides. For optimal performance, delay SDK initialization or data transmission until consent status is captured. For Android, implement the [start](https://dev.appsflyer.com/hc/docs/integrate-android-sdk#deferring-sdk-start) method. For iOS, implement either the [start](https://dev.appsflyer.com/hc/docs/integrate-android-sdk#deferring-sdk-start) method or the [waitForATTUserAuthorization](https://dev.appsflyer.com/hc/docs/integrate-ios-sdk#enabling-app-tracking-transparency-att-support) method.
   * **Note**: The AppsFlyer [Android SDK v6.13.0+](https://dev.appsflyer.com/hc/docs/android-release-notes) and [iOS SDK v6.13.0+](https://dev.appsflyer.com/hc/docs/ios-release-notes) are required for compliance.

#### Branch:

1. Integrate the [Branch SDK](https://help.branch.io/developers-hub/docs/native-sdks-overview).
2. Follow these [Android](https://help.branch.io/developers-hub/docs/android-full-reference#branch-provided-data-parameters-in-initsession-callback) and [iOS](https://help.branch.io/developers-hub/docs/ios-full-reference#parameters-1)deeplink guides to ensure that Google can receive referring URL click identifiers from Branch for attribution.
   * **Note**: The Branch [Android SDK v5.1.3+](https://github.com/BranchMetrics/android-branch-deep-linking-attribution/releases) and [iOS SDK v1.43.1+](https://github.com/BranchMetrics/ios-branch-sdk-spm/blob/main/ChangeLog.md) are required for compatibility.

Activate Integrated Conversion Measurement in the Branch UI by ensuring that the “Integrated Conversion Measurement” setting is enabled for (enabled by default), and [Attribution Windows for Click To Install](https://help.branch.io/docs/attribution-windows-link-settings) is set to 24 hours or longer (7 day default) for Google Ads.
   * **Note**: The Branch [iOS SDK v3.13.3+](https://github.com/BranchMetrics/ios-branch-deep-linking-attribution/releases) is required for compatibility (add *setSDKWaitTimeForThirdPartyAPIs* to the [*getInstance*](https://help.branch.io/developers-hub/docs/ios-full-reference#getinstance) method, set to 5 seconds or longer). However, all Branch Android SDK versions are compatible. Additionally for iOS, either the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required.
4. Provide [consent status](https://help.branch.io/using-branch/changelog/google-dma-compliance) for EEA users by following these [Android](https://help.branch.io/developers-hub/docs/android-advanced-features#google-dma-compliance) and [iOS](https://help.branch.io/developers-hub/docs/ios-advanced-features#google-dma-compliance) compliance guides. For optimal performance, delay SDK initialization or data transmission until consent status is captured. For Android, implement the `expectDelayedSessionInitialization()` method. For iOS, implement the `didFinishLaunchingWithOptions` method.
   * **Note**: The Branch [Android SDK v5.9.0+](https://github.com/BranchMetrics/android-branch-deep-linking-attribution/releases) and [iOS SDK v3.2.0+](https://github.com/BranchMetrics/ios-branch-sdk-spm/blob/main/ChangeLog.md) are required for compliance.

Follow these [Android](https://support.kochava.com/sdk-integration/android-sdk-integration/android-using-the-sdk/?scrollto=marker_7) and [iOS](https://support.kochava.com/sdk-integration/ios-sdk-integration/ios-using-the-sdk/?scrollto=marker_9) deeplink guides to ensure that Google can receive referring URL click identifiers from Kochava for attribution.

Collect app conversion events and user consent through a third-party AAP server-to-server integration
-----------------------------------------------------------------------------------------------------

Use third-party AAP server-to-server integration to collect and pass app conversion events to Google Ads for campaign attribution and optimization. To configure third-party server-to-server events:

#### Adjust:

1. Integrate the [Adjust S2S API](https://help.adjust.com/en/article/server-to-server-s2s-integration).
2. Additionally, configure the [Adjust SDK](https://help.adjust.com/en/article/get-started-with-adjust#phase-2-integrate-the-adjust-sdk-in-your-app-developer) to receive session\_start conversion events, to ensure Google can receive referring URL click identifiers from Adjust for attribution. View the above SDK section for additional guidance.
3. Activate Integrated Conversion Measurement in the Adjust user interface by ensuring “[Probabilistic Modeling”](https://help.adjust.com/en/article/attribution-methods#probabilistic-modeling) (disabled by default), and the [Attribution Window for Probabilistic Modeling](https://help.adjust.com/en/article/attribution-windows#attribution-1) is set to 24 hours (6 hours by default) for Google Ads.
   * **Note**: The Adjust [iOS SDK v5.4.1+](https://github.com/adjust/ios_sdk/releases) and [Adjust ODM plugin](https://dev.adjust.com/en/sdk/ios/plugins/google-odm) are required for compatibility. However, all Adjust Android SDK versions are compatible. Additionally for iOS, either the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required.
4. Provide consent status for EEA users by following this [compliance guide](https://dev.adjust.com/en/sdk/android/features/privacy/#provide-consent-data-to-google-digital-markets-act-compliance).

#### Airbridge:

1. Integrate the [Airbridge S2S API](https://help.airbridge.io/en/references/s2s-event).
2. [Contact](https://ab180help.zendesk.com/hc/en-us/requests/new) your Airbridge CSM for guidance to ensure Google can receive referring URL click identifiers from Airbridge for attribution.
3. Activate Integrated Conversion Measurement in the Airbridge UI by ensuring the [Lookback Window](https://help.airbridge.io/en/guides/setting-attribution-window) for [*Probabilistic Modeling Matching*](https://help.airbridge.io/en/guides/setting-attribution-window#how-to-view-the-settings) is set to 24 hours or longer (24 hours by default) for Google Ads.
   * **Note**: For iOS, the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required. Using either SDK, fetch the ODM info string value and pass it to the [Airbridge S2S](https://help.airbridge.io/en/references/s2s-event) API as odm\_info=[value].
4. Provide consent status for EEA users by following this [compliance guide](https://help.airbridge.io/en/guides/supporting-the-updated-google-eu-user-consent-policy#sharing-user-consent-with-airbridge).

#### AppsFlyer:

1. Integrate the [AppsFlyer S2S API](https://support.appsflyer.com/hc/articles/207034486-Server-to-server-events-API-for-mobile-S2S-mobile-).
2. [Contact](https://www.appsflyer.com/company/contact/) your AppsFlyer CSM for guidance to ensure Google can receive referring URL click identifiers from AppsFlyer for attribution.
3. Activate Integrated Conversion Measurement in the AppsFlyer user interface by ensuring that “Advanced Data Sharing” is enabled (disabled by default) for Google Ads.
   * **Note**: For iOS, the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required. Using either SDK, fetch the ODM *info* string value and pass it to the [AppsFlyer S2S API](https://support.appsflyer.com/hc/articles/207034486-Server-to-server-events-API-for-mobile-S2S-mobile-) as *odm\_info=[value]*.
4. Provide consent status for EEA users by following this [compliance guide](https://support.appsflyer.com/hc/en-us/articles/22310731147153-Supporting-the-Google-EU-consent-policy#how-consent-data-is-sent).

#### Branch:

1. Integrate the [Branch S2S API](https://help.branch.io/developers-hub/docs/attribution-api#api-setup).
2. Include the fields below to ensure Google can receive referring URL click identifiers from Branch for attribution:
   * For Android app install, pass “`install_referrer_extras`” field to <https://api2.branch.io/v1/open>
   * For Android app engagement, pass “`android_app_link_url`” field to <https://api2.branch.io/v1/open>
   * For iOS app engagement, pass “`universal_link_url`“ field to <https://api2.branch.io/v1/open>
3. Activate Integrated Conversion Measurement in the Branch user interface by ensuring that the “Integrated Conversion Measurement” setting is enabled for (enabled by default), and [Attribution Windows for Click To Install](https://help.branch.io/docs/attribution-windows-link-settings) is set to 24 hours or longer (7 day default) for Google Ads.
   * **Note**: For iOS, the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required. Using either SDK, fetch the ODM *info* string value and pass it to the [Branch S2S API](https://help.branch.io/developers-hub/docs/attribution-api#api-setup) as *odm\_info=[value]*.
4. Provide consent status for EEA users by following this [compliance guide](https://help.branch.io/using-branch/changelog/google-dma-compliance).

#### Kochava:

1. Integrate the [Kochava S2S API](https://support.kochava.com/server-to-server-integration/).
2. Include the fields below to ensure Google can receive referring URL click identifiers from Kochava for attribution:
   * For Android app install, pass “`referrer=value`” field/value to <https://control.kochava.com/track/json>
   * For Android app engagement, pass “`event_name=_deeplink`” and “`gclid=value`” fields/values to <https://control.kochava.com/track/json>
   * For iOS app engagement, pass “`event_name=_deeplink`” and “`gclid=value`” and “`gbraid=value`” fields/values to <https://control.kochava.com/track/json>
3. Activate Integrated Conversion Measurement in the Kochava user interface by ensuring [Privacy Profiles](https://support.kochava.com/create-manage-apps/creating-and-editing-privacy-profiles/) and [Modeled Attribution](https://support.kochava.com/glossary/modeled-attribution/) are enabled (enabled by default for Android, disabled by default for iOS), and the [Click Reconciliation for Modeled Lookback](https://support.kochava.com/campaign-management/partner-reconciliation-settings/) is set to 24 hours or longer (7 day default for Android, disabled by default for iOS) for Google Ads.
   * **Note**: For iOS, the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required. Using either SDK, fetch the ODM *info* string value and pass it to the [Kochava S2S API](https://support.kochava.com/server-to-server-integration/) as *odm\_info=[value]*.
4. Provide consent status for EEA users by following these [Install](https://support.kochava.com/server-to-server-integration/install-notification-setup/#marker_5) and [Post-Install Event](https://support.kochava.com/server-to-server-integration/post-install-event-setup/#marker_2) compliance guides.

#### Singular:

1. Integrate the [Singular S2S API](https://support.singular.net/hc/articles/360037640812--UPDATED-Server-to-Server-S2S-Integration-Guide).
2. Include the fields below to ensure Google can receive referring URL click identifiers from Singular for attribution:
   * For Android app install, pass “`install_ref`” field to <https://s2s.singular.net/api/v1/launch>
   * For Android app engagement, pass “`openuri`” field to <https://s2s.singular.net/api/v1/launch>
   * For iOS app engagement, pass “`openuri`” field to<https://s2s.singular.net/api/v1/launch>
3. Activate Integrated Conversion Measurement in the Singular user interface by ensuring that “Integrated Conversion Measurement” is enabled (enabled by default), and the [Attribution Lookback Window](https://support.singular.net/hc/en-us/articles/115000526963-Understanding-Singular-Mobile-App-Attribution#The_Attribution_Lookback_Window) for [Probabilistic Attribution](https://support.singular.net/hc/en-us/articles/360002290752-Probabilistic-Attribution-FAQ) is set to 24 hours (24 hours by default) for Google Ads.
   * **Note**: For iOS, the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required. Using either SDK, fetch the ODM *info* string value and pass it to the [Singular S2S API](https://support.singular.net/hc/articles/360037640812--UPDATED-Server-to-Server-S2S-Integration-Guide) as *odm\_info=[value]*.
4. Provide consent status for EEA users by following this [compliance guide](https://support.singular.net/hc/en-us/articles/115003252786-Google-Ads-AdWords-Mobile-Attribution-Integration#EEA_User_Consent_Handling).

#### Tenjin:

1. Integrate the Tenjin S2S API (available for paid clients by request).
2. [Contact](https://tenjin.com/contact-us/) your Tenjin CSM for guidance to ensure Google can receive referring URL click identifiers from Tenjin for attribution.
3. Activate Integrated Conversion Measurement in the Tenjin user interface by ensuring that “Probabilistic Matching” is enabled (enabled by default), and the [Attribution Window for Probabilistic Matching](https://docs.tenjin.com/docs/attribution-window-setup) is set to 24 hours (1 hour by default) for Google Ads.
   * **Note**: For iOS, the Firebase [iOS SDK v11.14.0+](https://github.com/firebase/firebase-ios-sdk/releases) or [on-device conversion standalone SDK](https://support.google.com/google-ads/answer/16384720) is required. Using either SDK, fetch the ODM *info* string value and pass it to the Tenjin S2S API as *odm\_info=[value]*.
4. [Contact](https://tenjin.com/contact-us/) your Tenjin CSM for guidance to provide consent status for EEA users.
